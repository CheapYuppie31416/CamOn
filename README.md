# CamOn

CamOn is a webcam-triggered voice bot that runs entirely on your own hardware. When the camera sees a face, CamOn starts a short spoken conversation. It asks a question, listens to the answer, has a local language model work out what the person meant and write a reply, and says the reply out loud.

The conversation is defined in a YAML **flow** file, so CamOn can run many simple request/response conversations without code changes. Two flows are included:

- **joke**: *"Do you want to hear a joke?"* If yes, it asks for a topic and tells a joke about it. If no, it roasts them (PG-rated) for saying no.
- **history**: *"Would you like to hear a fact from history?"* If yes, it asks for a topic or time period and shares a fact. If no, it tells them how a famous historical figure died.

CamOn was built for an NVIDIA DGX Spark, but runs on any Linux machine with a webcam, a microphone, a speaker and an OpenAI-compatible LLM server such as vLLM.

## Quick start

### With Docker (CamOn + vLLM together)

**Before the first start, download the model.** `docker-compose.yml` serves `nvidia/Qwen3.6-35B-A3B-NVFP4` from your Hugging Face cache, `~/.cache/huggingface`, which is mounted into the vLLM container. Download it there once:

```bash
pip install -U huggingface_hub              # provides the `hf` command
hf auth login                               # only needed if the model page asks you to accept terms
hf download nvidia/Qwen3.6-35B-A3B-NVFP4    # tens of GB; resumes if interrupted
```

If the model isn't in the cache, vLLM tries to download it on its first start instead. That is slower, and it can take longer than the 20 minutes the health check allows for start-up. vLLM would then be marked unhealthy and CamOn would not start. To use a different model, download it the same way and change the model name in the `vllm-qwen` service's `command:`.

Then start everything:

```bash
cd ~/CamOn
docker compose up -d --build      # first start builds CamOn's image and loads the model
docker compose logs -f camon      # watch the conversations
docker compose down               # stop everything
```

CamOn waits until the vLLM container reports healthy before it starts. Audio uses the host's PipeWire session, so CamOn speaks through the default output and listens on the default input, both set in **Settings → Sound**. Put CamOn options on the `command:` lines in `docker-compose.yml`.

### Directly on the host

```bash
sudo apt install -y espeak-ng alsa-utils v4l-utils libportaudio2 ffmpeg python3-venv
python3 -m venv ~/greeter-venv && source ~/greeter-venv/bin/activate
pip install opencv-python kokoro-onnx faster-whisper sounddevice numpy pyyaml scipy

curl http://localhost:8000/v1/models          # check your vLLM server is up
python cam_on.py --say "Testing, one two three" # check the voice
python cam_on.py                               # run the joke flow
python cam_on.py --flow history --record       # run the history flow and record it
```

On first run CamOn downloads the YuNet face model (~230 KB), the Kokoro voice (~340 MB) and the Whisper model (~150 MB for `base.en`). Later runs reuse them.

## Theory of operation

```
 camera ──► face detection ──► (face arrives) ──► flow runner ──┬─► speak (Kokoro) ──► speaker
                                                                │
 microphone ──► always-open stream ──► speech detection ──► speech-to-text ──► LLM (vLLM)
                       │                  (Silero VAD)        (Whisper)       interprets / writes
                       └──► recorder (optional)
```

1. **Watching.** OpenCV reads the webcam, and the **YuNet** face detector checks a few frames per second. A face has to be seen in several consecutive checks before it counts, and faces smaller than `--min-face` (people far away) are ignored. When a new person arrives, CamOn starts a conversation. It won't start another until that person has left (`--absent-seconds`) and a short `--cooldown` has passed.

2. **Talking.** The flow runner steps through the YAML flow. Speech is generated by **Kokoro**, a small neural text-to-speech model run with ONNX Runtime, and played with `aplay` through PipeWire. If Kokoro can't start, CamOn falls back to espeak-ng.

3. **Listening, even while talking.** The microphone stays open the whole time. Listening starts as soon as a question begins, so people can answer over the bot. **Silero VAD** decides which audio is speech. The bot also hears its own voice through the microphone, so during a question your voice only counts if it is clearly louder than the echo (`--barge-factor`). Afterwards, CamOn removes any of the question's own words from the transcript. An answer ends after `--end-silence` seconds of quiet.

4. **Understanding.** **faster-whisper**, an efficient Whisper implementation, turns the answer into text. For a multiple-choice step, the **LLM** picks which label the answer means (for example `yes`, `no` or `unclear`), always at temperature 0 so the same answer is read the same way. Reasoning models are asked to skip their "thinking" step so replies come back quickly.

5. **Replying.** For a `generate` step, the LLM writes the reply (a joke, a fact, a roast) from the flow's prompt. CamOn removes markdown and emoji, then speaks it. Every `generate` step can have a fallback line, used if the model is unavailable.

6. **Recording (optional).** With `--record`, each conversation is saved to its own folder: video with sound (`conversation.mp4`), the raw microphone audio (`audio.wav`) and a timestamped log of what was said and heard. Each recording includes the 2 seconds before the conversation started. The video is written at a steady frame rate so it stays in sync with the audio, and **ffmpeg** combines the two.

### Technologies

| Part | Technology |
|---|---|
| Face detection | OpenCV + YuNet (ONNX) |
| Speech detection | Silero VAD (the copy bundled with faster-whisper, run with ONNX Runtime) |
| Speech-to-text | faster-whisper (CTranslate2), CPU int8 |
| Language model | Any OpenAI-compatible server, e.g. vLLM serving Qwen3.6 |
| Text-to-speech | Kokoro via kokoro-onnx (espeak-ng fallback) |
| Audio I/O | PortAudio (sounddevice) and ALSA `aplay`, through PipeWire |
| Recording | OpenCV VideoWriter + WAV, combined with ffmpeg |
| Conversations | YAML flows (PyYAML) |
| Deployment | Docker Compose (vLLM container + CamOn container) |

## Conversation flows

Flows live in `flows/`. Run one by name (`--flow history`) or by path (`--flow ~/my_flow.yaml`). Each step does one thing, then moves to its `next` step. A step with no `next` ends the conversation.

| Step | What it does |
|---|---|
| `say` | Speak fixed text. |
| `ask` | Speak a question and listen. `save_as: name` keeps the reply as `{name}` (with an optional `default:` if nothing is heard). `classify:` lets the LLM pick one of your labels; each label has `means:` (a description for the model) and `next:`. If nothing is heard, or the model's answer isn't a label, the **last** label is used. |
| `generate` | Have the LLM write text from `system` + `prompt` and speak it. Optional: `temperature` (default 0.9; higher means more varied), `max_tokens` (default 150), `fallback`, `save_as`. |

At the top level of a flow file:

- **`start`** (required): the first step.
- **`easter_eggs`**: patterns checked on every reply. When one matches, its line is spoken and the question is asked again.
- **`on_error`**: the line spoken if something goes wrong.
- **`name`, `version`, `author`** (optional): override CamOn's own values.

Text can use `{variables}`: `{name}`, `{version}`, `{author}` and anything saved with `save_as`. CamOn checks a flow when it loads it and lists every problem by step name: unknown keys, a `next:` pointing to a missing step, misspelled variables, bad patterns. See `flows/joke.yaml` for a fully commented example.

## Command-line options

| Option | Default | What it does |
|---|---|---|
| `--flow FLOW` | `joke` | Conversation to run: a name from `flows/` or a path to a YAML file. |
| `--version` | | Print the version and exit. |
| **Camera** | | |
| `--camera CAMERA` | `0` | Camera index or `/dev/videoN`. `v4l2-ctl --list-devices` lists cameras. |
| `--min-face PIXELS` | `60` | Ignore faces smaller than this, so only people close by are asked. |
| `--absent-seconds S` | `1` | How long no face must be seen before a new arrival can start a conversation. |
| `--cooldown S` | `3` | Minimum seconds between the end of one conversation and the start of the next. |
| `--no-window` | off | Run without the video window (for headless use or Docker). |
| `--record [FOLDER]` | off | Record each conversation (video, audio, log). The folder defaults to `recordings/`. |
| **Listening** | | |
| `--mic MIC` | system default | Microphone index or part of its name. |
| `--list-mics` | | List microphones and exit. |
| `--whisper-model NAME` | `base.en` | Speech-to-text model: `tiny.en` (fastest), `base.en`, `small.en` (more accurate, slower), ... |
| `--vad-threshold P` | `0.5` | How sure Silero must be that it's hearing speech (0–1). Lower it (0.3) if quiet answers are missed; raise it (0.7) if noises start recordings. |
| `--answer-wait S` | `6` | How long to wait for someone to start answering. |
| `--end-silence S` | `1.0` | Seconds of quiet that end an answer. |
| `--barge-factor X` | `3.0` | While the bot is talking, your voice must be this many times louder than room noise to count. About 1.5 works with PipeWire echo cancellation. |
| **Language model** | | |
| `--llm-url URL` | `http://localhost:8000/v1` | OpenAI-compatible API base URL (vLLM). |
| `--llm-model NAME` | first listed | Model to use; by default, the first model the server lists. |
| **Voice** | | |
| `--voice NAME` | `af_heart` | Kokoro voice. The first letter is the accent (`a` US, `b` British), the second the gender (`f`/`m`), e.g. `am_michael`, `bm_george`. |
| `--speed X` | `1.0` | Speaking speed (0.8 is slower, 1.2 faster). |
| `--list-voices` | | List Kokoro voices and exit. |
| `--say TEXT` | | Speak the text with the chosen voice and exit (a voice test). |

Settings you're unlikely to need to change are constants near the top of `cam_on.py`: camera resolution, detection rate, face confidence, the Whisper device, recording frame rate and pre-roll, and so on.

## Tips

- **Speaker or microphone not working:** check the defaults with `wpctl status`. If a Sunshine/Moonlight session is connected, Sunshine can take over the default output; turn on "play audio on host" in Moonlight.
- **Answers over the bot's voice are missed, or its own voice triggers it:** turn on PipeWire's WebRTC echo cancellation (`module-echo-cancel`) and use `--barge-factor 1.5`, or adjust `--barge-factor` up or down.
- **A recorded `.mp4` looks blank in Ubuntu's Videos app:** install `gstreamer1.0-libav`, or use VLC or `ffplay`.
- **Recording people:** in some places, including California, recording a conversation needs everyone's consent, so let people know when `--record` is on.
